# Постраничная миграция фронтенда на Inertia + Mantine

Фронтенд состоит из 21 Blade-страницы на Bootstrap 5 и одной Inertia-страницы на react-bootstrap; данные попадают в React тремя разными способами, работают два независимых React-рантайма, типизации данных с бэкенда нет. Решено переводить страницы на Inertia + Mantine + TypeScript **по одной, по PR на страницу**, с редизайном внутри миграции, а не отдельным проектом.

Это означает, что несколько месяцев на сайте одновременно живут два CSS-фреймворка и две разные шапки. Это **сознательное состояние, а не недоделка**. Критерий выхода — последняя Blade GET-страница; после неё удаляются Bootstrap, jQuery, lodash, `@rails/ujs`, `laracasts/flash` и `Paginator::useBootstrap()`.

## Considered Options

**Big bang в одной ветке** отвергнут: проект volunteer-driven, долгоживущая ветка с переписыванием 21 страницы умрёт от конфликтов раньше, чем будет смержена.

**Редизайн отдельным проектом до/после миграции** отвергнут пользователем сознательно: цель — современный вид, и делать одну и ту же вёрстку дважды бессмысленно. Цена — PR-ы нельзя ревьюить «один-в-один», нужны скриншоты.

## Consequences

- Каждый PR меняет и разметку, и внешний вид одновременно — ревью только по скриншотам
- Шапка и футер в фазе 1 делаются максимально похожими на текущие Bootstrap-версии, иначе каждый переход между половинами выглядит как баг. Редизайн шелла — первый PR фазы 2
- Состав навигации считает один PHP-класс, а Blade и Mantine его только рендерят: иначе два меню разъедутся (они уже разъехались — `admin/users/edit.blade.php` потерял пункт Export)
- Конфликта CSS-каскада нет: Inertia-корень (`resources/views/app.blade.php`) и Blade-лейаут (`resources/views/layouts/app.blade.php`) — два независимых документа, переход между ними всегда полная перезагрузка. Условие: Bootstrap и Mantine не должны встретиться в одном документе

Детали объёма, порядка PR-ов и конвенций — в [docs/frontend-migration.md](../frontend-migration.md).
