# SSR отложен: публичные страницы остаются на Blade, три страницы переезжают в SEO-долг

Inertia SSR требует JS-рантайма: `renderToString` умеет выполнять только Node, PHP и nginx этого не могут (nginx раздаёт собранный бандл как файлы — это не то же самое, что исполнять React на сервере). В основном Hexlet SSR живёт отдельным контейнером-сайдкаром (`bin/vite ssr`, порт 13714, requests 300Mi / limit 500Mi). У нас же весь Heroku-dyno даёт 512 МБ на всё вместе с PHP-FPM и nginx, то есть Node туда, скорее всего, просто не влезет.

Поэтому решено: **фаза 1 идёт без SSR**, публичные страницы (`landing`, `home`, `pages/*`, `chapter/*`, `exercise/*`, `user/*`, `rating/*`, `auth/*`) остаются на Blade — их HTML по-прежнему рендерит PHP, и SEO не страдает. Решение о размещении SSR-сайдкара принимается на входе в фазу 2.

Весь код фазы 1 при этом пишется SSR-совместимым: никаких `window`/`document`/`localStorage` на верхнем уровне модулей, респонсив только через CSS-механизмы Mantine, даты форматируются на бэкенде внутри DTO.

## Принятый SEO-долг

Три страницы фазы 1 **публичны и индексируются**, хотя выглядят как приватные — ни у одной нет auth-middleware, а `public/robots.txt` закрывает только `*/register`, `*/login`, `*/oauth/`, `*/users/`, `/en/` и `*?`:

- `log/index` (`ActivityController`)
- `comment/index` (`CommentController@index`, политика `viewAny → true`)
- `solution/index`

Решено переносить их всё равно. До появления SSR краулер будет получать на этих URL пустой `<div id="app">` с JSON в `data-page`. Долг снимается вместе с включением SSR в фазе 2; тогда же надо проверить в Search Console, не просела ли органика на `/solutions`.

`solution/show` тоже публичен, но уже отдаёт `noindex, nofollow` (`resources/views/solution/show.blade.php:3`) — риска нет.

## Considered Options

**Оставить публичные страницы на Blade навсегда** — тогда «современный вид» получает меньше половины сайта, а `layouts/app.blade.php` с Bootstrap живёт вечно. Отвергнуто: цель миграции — весь сайт.

**Перенести всё сразу на CSR** — отвергнуто: `exercise/*` и `chapter/*` дают проекту основной органический трафик, а `exercise/show` подтягивает текст условия из 356 файлов `exercise/listing/**`. Google исполняет JS неохотно, Яндекс хуже.

**Prerender на этапе сборки** (Node только в билде) — покрывает всего 3 страницы из ~10 публичных: `chapter/*`, `exercise/*`, `user/*` и `rating/*` зависят от прогресса конкретного пользователя и предрендериться не могут.

**V8Js вместо Node** (`spatie/laravel-server-side-rendering` умеет этот движок) — единственная техническая лазейка без Node-процесса, но расширение фактически заброшено, а на Heroku PHP-билдпаке его не собрать без своего билдпака.

## Consequences

- `resources/views/app.blade.php` (Inertia-корень) надо научить принимать `description`, `robots` и `hreflang` — сейчас там нет ни того, ни другого, а `<title>` жёстко `config('app.name')`. Без этого каждая перенесённая страница теряет description и hreflang
- Три страницы получают `robots` пропом; для `log/index` и `comment/index` разумно поставить `noindex` сразу — SEO-ценности у ленты активности и ленты комментариев нет
- Когда SSR включится, `Inertia` деградирует до CSR при падении сайдкара: сайт не ляжет, но SEO тихо пропадёт, и узнать об этом можно будет только по графикам трафика. Нужен health-check на порт SSR
