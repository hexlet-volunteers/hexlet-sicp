# Ручная разметка автотестов в TestOps

Снимок сделан **2026-08-18**, до первой заливки результатов из CI, проект
`hexlet-sicp` (id 100).

**Восстанавливать по нему ничего не нужно.** Заливка прошла, и TestOps имён
тест-кейсов не перезаписал — см. раздел «Наблюдённое поведение» в
[ADR-0005](adr/0005-code-owns-testops-case-names.md). Файл остался справочником
«тест → имя + `Feature`», а не аварийной копией.

## Зачем этот файл

Имена и `Feature` у этих тест-кейсов кто-то расставил вручную в интерфейсе TestOps.
По ADR-0005 источником истины для имени автотеста стал код. Файл собирался в ожидании,
что первая заливка перетрёт эти имена техническими, — этого не произошло. Пользу он
сохранил другую: по нему видно, какие имена и `Feature` уже осмыслены человеком, то
есть с чего начинать разметку через `#[DisplayName]`, когда до неё дойдёт дело.

Файл — снимок, а не источник истины. Как только строка перенесена в код через
`#[DisplayName]`, она здесь больше не нужна.

## Что заметно по списку

- **Кейсы 164 и 206 названы одинаково** — «Открытие главной страницы», хотя это разные
  тесты (`testNotSeeDevLogin` и `testIndex`). Переносить эту пару в код как есть нельзя,
  имена надо развести.
- Значения `Feature` — десять групп: Главная страница, Главы книги, Комментарии,
  Лог активностей, Мое обучение, Публичный профиль, Раздел страниц, Сохраненные решения,
  Упражнения, Sitemap. Это готовая карта для будущих `#[Feature]`-атрибутов.
- Часть описаний — просто URL страницы на проде. Как описание теста они бесполезны,
  переносить их в код не стоит.
